## Verdict / 结论

The previous round's SMTP defects (never reading the 220 greeting, no `encryption` normalisation) really were fixed, and CRLF filtering moved down into the driver layer. But this round shows the fix **only covered one of the two drivers**: NativeMailer bypasses every one of those hardenings.

上一轮的 SMTP 硬伤（未读 220 问候语、encryption 未归一）确实修好了，CRLF 过滤也下沉到了驱动层。但本轮发现**修复只覆盖了 SmtpMailer 一条路径**：NativeMailer 整条链路绕过了这些加固。

## P0

### P0-1

- **Status / 状态**: Open
- **Where / 位置**: `src/NativeMailer.php:24-28`, `src/Mail.php:84-87`
- **Verification / 验证**: reproduced
- **EN**: NativeMailer does not filter the subject for CRLF and does not apply RFC 2047 encoding either — it passes it straight as the second argument to `mail()`, and `withSubject()` validates nothing. `withSubject("real\r\nBcc: evil@example.com")` kept the CRLF intact. The same input is stripped by SmtpMailer, so the two drivers have different security levels
- **中文**: NativeMailer 的 subject 完全不做 CRLF 过滤，也不做 RFC 2047 编码，直接作为 `mail()` 第二参传入；而 `withSubject()` 无校验。实测 `withSubject("real\r\nBcc: evil@example.com")` 原样保留。SmtpMailer 同输入会被剥离 —— 两驱动安全等级不一致

### P0-2

- **Status / 状态**: Open
- **Where / 位置**: `src/NativeMailer.php:14-33`
- **Verification / 验证**: reproduced (zero references in source)
- **EN**: NativeMailer ignores attachments entirely: it never references `$mail->attachments` and never builds a multipart body. Sending with an attachment silently drops it and reports no error
- **中文**: NativeMailer 完全忽略附件：全程不引用 `$mail->attachments` 也不生成 multipart。带附件发送会静默丢掉附件且不报错

## P2

### P2-1

- **Status / 状态**: Open
- **Where / 位置**: `src/Mail.php:25-39`, `src/SmtpMailer.php:52,54`
- **Verification / 验证**: static
- **EN**: The public constructor `new Mail(from: ...)` bypasses all address validation, while the SMTP side splices `MAIL FROM:<...>` / `RCPT TO:<...>` from raw values — an envelope command injection surface
- **中文**: 公共构造器 `new Mail(from: ...)` 绕过全部地址校验，而 SMTP 侧 `MAIL FROM:<...>` / `RCPT TO:<...>` 用原值拼接，构成信封命令注入面

### P2-2

- **Status / 状态**: Open
- **Where / 位置**: `src/SmtpMailer.php:194,199-207`
- **Verification / 验证**: static
- **EN**: `expect()` only stops reading when `substr($line,3,1) === ' '`, so a legal bare status line (`"250\r\n"`) makes it swallow the next response and desynchronise the session; when a multi-line response is cut off at a non-continuation line, the truncated response is treated as success
- **中文**: `expect()` 仅在 `substr($line,3,1) === ' '` 时结束读取，合法的裸状态码行（`"250\r\n"`）会让它把下一条响应并进来，导致会话错位；多行响应在非续行处断连时截断响应会被当作成功

### P2-3

- **Status / 状态**: Open
- **Where / 位置**: `src/SmtpMailer.php:80-82,69,93,106-115`
- **Verification / 验证**: `src/NativeMailer.php:37-57`
- **EN**: Configuring only the username or only the password silently skips authentication; the STARTTLS probe is case-sensitive and misses the trailing `250 STARTTLS` form; a cc/bcc-only message emits an empty `To:`; the two drivers apply custom headers in opposite precedence
- **中文**: 只配 username 或只配 password 时静默跳过认证；STARTTLS 检测大小写敏感且不认末行形态 `250 STARTTLS`；仅 cc/bcc 时输出空 `To:`；两驱动的自定义头优先级相反
