# P3-7 — SmtpMailer::send() does dot-escaping with str_replace("\r\n.", …

## Finding / 问题

- EN: SmtpMailer::send() does dot-escaping with str_replace("\r\n.", "\r\n..", ...) which does not escape a line starting with "." if it is the very first character of the entire message (though in practice headers always come first).
- 中文: SmtpMailer::send() 通过 str_replace 做点转义，若正文第一行以 "." 开头且是整个消息的第一个字符则不会被转义（但实际中前面总有 headers）。
- Where / 位置: `src/SmtpMailer.php:57`
- Verification / 验证: static / 仅静态推断

## Thread

- 2026-09-28 · `reviewer — migears-full-review` · `open` — filed from the 5th round.
- 2026-10-01 · `owner — migears-mail` · `rejected` — the gap is unreachable, so the transformation already equals the RFC 5321 transparency rule for every input this module can produce. `SmtpMailer::buildMessage()` (`src/SmtpMailer.php:93-147`) always writes the headers first and `From` is unconditionally one of them (`:97`), so the message's first character is always the first character of a field name, never `.`. Every later line is either a header line or base64-encoded content (`chunk_split(base64_encode(...))` at `:137` / `:143` and `:168` — the base64 alphabet contains no `.`), and MIME boundary lines begin with `--` (`:134`, `:141`). The existing `str_replace("\r\n.", "\r\n..", ...)` therefore covers every line that can occur. Probe (outside the repo, via `vendor/autoload.php`, reflecting on `buildMessage()`): plain, HTML and custom-header messages all begin with `'F'`, and no line starts with `.` except a custom header literally named `.` (`.: val`), which is never the first line and is escaped on the wire to `..: val`. Re-grade: filed P3 (metadata/doc drift); it is a robustness claim with no reachable input.
  中文：该缺口不可达，故对本模块能产出的任何输入，这段变换都已等价于 RFC 5321 透明规则。`SmtpMailer::buildMessage()`（`src/SmtpMailer.php:93-147`）总是先写头，且 `From` 必在头中（`:97`），因此报文首字符永远是字段名的首字符，不可能是 `.`。其后的每一行要么是头行，要么是 base64 内容（`chunk_split(base64_encode(...))`，见 `:137`/`:143`/`:168`——base64 字母表不含 `.`），MIME 边界行以 `--` 开头（`:134`、`:141`）。现有 `str_replace("\r\n.", "\r\n..", ...)` 因此覆盖了所有可能出现的行。探针（仓库外，经 `vendor/autoload.php` 反射 `buildMessage()`）：纯文本、HTML、自定义头三种报文均以 `'F'` 开头，除一个名为 `.` 的自定义头（`.: val`）外无行以 `.` 开头，而该行既非首行、上线时也被转义为 `..: val`。重新定级：立案为 P3（元数据/文档漂移），实为无任何可达输入的健壮性主张。
