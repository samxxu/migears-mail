# P2-3 — `charset` is interpolated into the `Content-Type` parameter unescaped, …

## Finding

- `charset` is interpolated into the `Content-Type` parameter unescaped, so a value carrying a quote breaks the parameter and can add parameters to the same header — the same shape as P2-2, on an expression that fix did not touch. Probed by the module owner through this module's own `vendor/autoload.php`, from a directory outside the repository: `withCharset('utf-8\"; x=\"y')` yields `Content-Type: text/plain; charset=utf-8\"; x=\"y`, an extra `x` parameter. It appears in the main header (`src/NativeMailer.php:111`, `src/SmtpMailer.php:117`) and in the alternative body part (`src/NativeMailer.php:52`, `src/SmtpMailer.php:135`).

- Where: `src/NativeMailer.php:111 · src/SmtpMailer.php:117 · src/NativeMailer.php:52 · src/SmtpMailer.php:135`
- Verification: reproduced

# P2-3 — `charset` 未转义地被插进 `Content-Type` 参数，因此带引号的取值会破坏参数、并向同一头注入额外参数——与 P2-2 …

## 问题

- `charset` 未转义地被插进 `Content-Type` 参数，因此带引号的取值会破坏参数、并向同一头注入额外参数——与 P2-2 同形，落在 P2-2 的修复没有触及的表达式上。由模块主经本模块自身 `vendor/autoload.php`、在仓库之外的目录里探得：`withCharset('utf-8\"; x=\"y')` 得 `Content-Type: text/plain; charset=utf-8\"; x=\"y`，多出一个 `x` 参数。出现于主导头（`src/NativeMailer.php:111`、`src/SmtpMailer.php:117`）与正文分部（`src/NativeMailer.php:52`、`src/SmtpMailer.php:135`）。

- 位置：`src/NativeMailer.php:111 · src/SmtpMailer.php:117 · src/NativeMailer.php:52 · src/SmtpMailer.php:135`
- 验证：已实证
